# 常见问题

## 可以直接在米家添加一个九牧设备卡片吗？

本方案使用虚拟事件触发 HA 操作，不创建米家原生设备卡片。米家中显示场景 / 自动化入口；完整开关、档位、按钮和设备状态集中在 HA 面板。

## 必须运行 Home Assistant 吗？

本教程是依赖 HA 的接入路线。仅有小米中枢网关、路由器或中控屏，不能运行本组件；本版不提供脱离 HA 的独立桥接服务。

## 系统蓝牙配对被拒绝，是不是要模拟整个小程序？

系统配对和 BLE GATT 通信不是同一件事。本集成实现相应的 BLE 查询与控制协议，不需要运行或分发原厂小程序。请先确认设备型号、蓝牙地址、适配器和连接占用，不能仅凭“配对失败”判断协议连接失败。

## 一台手机连上后，另一台或 HA 搜不到

已测试设备表现为单连接占用，连接后可能停止广播。退出小程序不一定立即释放连接；测试时可在手机系统设置关闭蓝牙。在 HA 中先开启「释放蓝牙给小程序」可阻止主机反复抢回连接。

## 为什么时不时显示不可用？

依次检查：

1. 「释放蓝牙」是否开启：开启时控制实体不可用是正常行为。
2. 手机是否仍连接设备：断开手机后再恢复 HA。
3. 信号与遮挡：先把适配器移到马桶附近测试。三堵墙等遮挡环境不能仅靠提高重试次数解决。
4. HA Bluetooth、宿主 BlueZ、USB 直通、D-Bus 是否正常。
5. 日志是“未发现设备”“状态不完整”还是“设备忙 / 设置未生效”。后两类不应一律当作蓝牙故障。

不要为了排查而频繁给马桶断电，也不要让多个桥接程序同时连接同一台马桶。

## 延迟大、要点几次才有效

稳定时使用保持连接模式，避免每次控制重新扫描。主机距离、USB 干扰、电话占用、事件链路延迟及设备忙都可能造成等待。

先比较 HA 直接操作与米家操作：若 HA 快而米家慢，检查网关事件到达时间和自动化轨迹；若两者都慢，检查蓝牙与设备状态。连续点击只会增加请求；机械动作超时后应先看现场，不能假定没执行。

## 网关收到事件但没有动作

核对事件名称是否与生成表完全一致、事件属性是否叫 `事件名称`、路由中的实体 ID 是否存在。手机表单不加引号或方括号。网关恢复时首个事件及超过 30 秒的历史事件会被路由过滤，可在自动化轨迹查看原因。

## 所有设置都读得到，但改一个设置被拒绝

当前写入需要设备空闲且状态完整。光感夜灯优先、落座检测、清洗运行或故障位都可能触发拒绝。ZS800J 组合设置还需保留喷杆、压力等原状态；字段不完整或不在已知范围时程序不会猜值写入。

## Linux 把设备误当经典蓝牙连接怎么办？

仅在日志已确认 BR/EDR 路径导致失败、且该适配器不承担普通蓝牙键鼠 / 音箱时，可以研究 BlueZ 的 BLE-only 模式。在 `/etc/bluetooth/main.conf` 的 `[General]` 段设置 `ControllerMode = le`，再按系统方式重启蓝牙服务。

这会影响该控制器的经典蓝牙功能，不是默认安装步骤。修改前备份原文件，恢复时还原配置并重启服务。不要为“可能更快”而直接套用；优先解决距离、占用和驱动问题。

## 换了名称或重装后面板实体不存在

实体 ID 包含型号与 MAC。生成器假定使用新安装的默认 ID；HA 可能保留旧实体或给重名 ID 添加编号。以「开发者工具 → 状态」中的实际实体 ID 为准，更新生成路由和面板即可。设备显示名称与实体 ID 是不同字段。

## 其他九牧型号能用吗？

目前不保证。即使广播名或 UUID 相同，不同型号仍可能使用不同命令。请提交型号、脱敏协议证据和测试说明，不要通过选择相近型号尝试机械操作。
