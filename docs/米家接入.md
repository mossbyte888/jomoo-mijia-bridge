# 米家接入教程

目标是把米家场景中的一个虚拟事件映射为一项 HA 实体操作。完整设备面板在 HA；米家负责场景和自动化触发。

## 操作前需要记录的信息

| 需要记录 | 在哪里查 | 用于哪一步 |
| --- | --- | --- |
| 马桶型号 | 铭牌 / 九牧小程序 | 添加集成和生成配置 |
| 每台马桶的蓝牙 MAC | HA Bluetooth 信息 / Linux 扫描 | `--device` 参数 |
| 网关虚拟事件实体 ID | HA 中枢网关的实体页 | `--gateway-event` 参数 |
| 实际马桶实体 ID | HA「开发者工具 → 状态」 | 检查生成路由是否对应 |

先在 HA 直接控制一次灯光。若这里已经失败，先处理蓝牙问题；米家路由不会修复蓝牙连接。

## 1. 找到网关事件实体

在 HA「设置 → 设备与服务 → Xiaomi Home → 中枢网关」中找到虚拟事件实体，复制其 **实体 ID**，例如 `event.example_gateway_virtual_event`。示例 ID 不能直接使用。

### 怎样复制实体 ID

1. 打开中枢网关设备页，点击名称包含「虚拟事件」的实体。
2. 在实体详情的设置入口查看 **实体 ID**，复制完整的 `event.xxx`；不要复制中文显示名称。
3. 也可打开「开发者工具 → 状态」，按 `event.` 或网关名称筛选，在左侧实体列表定位目标。
4. 如果有多个相似条目，逐个对照设备归属和事件时间，不要随便选一个。

### 做一次不控制马桶的测试

1. 手机米家进入「智能 / 自动化」页，点击添加，条件选择「手动执行」。
2. 执行动作选择自己的中枢网关，再选择「产生虚拟事件」。
3. 事件名称输入 `jomoo_connection_test`，保存场景并执行一次。
4. 回到 HA「开发者工具 → 状态」，观察刚才找到的实体。这条测试名称不在控制路由中，不会操作马桶。

应当看到：

- 实体状态为本次事件时间；
- 属性 `事件名称` 为手机输入的名称。

本版生成器使用中文属性键 **`事件名称`**。若你的集成返回其他键，应修改生成文件中的 `event_name` 提取表达式。不要把用于发送事件的 `notify.` 实体填到 `--gateway-event`。

## 2. 生成路由、面板和名称表

在下载解压后的仓库目录运行（需 Python 3.10+，无需安装 Python 依赖）：

```bash
python3 scripts/generate_config.py \
  --device sq9650=sq9650=AA:BB:CC:DD:EE:01 \
  --device zs800j=zs800j=AA:BB:CC:DD:EE:02 \
  --gateway-event event.example_gateway_virtual_event \
  --output output
```

每个 `--device` 参数的格式为 `别名=型号=MAC`：

- 别名决定米家事件前缀，只用小写字母、数字、下划线，并以字母开头。
- 型号必须是 `sq9650` 或 `zs800j`。
- MAC 必须替换为添加集成时输入的真实地址。
- 仅有一台时删去另一行；同型号多台可用 `bathroom_a`、`bathroom_b` 等不同别名。

### 不熟悉命令行时怎么运行

1. 在自己的电脑安装 Python 3.10 或更高版本；无需在 HA 主机或 NAS 安装 Python。
2. 在解压后的项目目录打开终端。macOS / Linux 可先输入 `cd `，再将项目文件夹拖入终端并回车；Windows 可在该目录打开 PowerShell。
3. macOS / Linux 使用上方多行命令。Windows PowerShell 请使用下面的一行命令，避免反斜杠换行语法不同：

```powershell
py -3 scripts/generate_config.py --device sq9650=sq9650=AA:BB:CC:DD:EE:01 --device zs800j=zs800j=AA:BB:CC:DD:EE:02 --gateway-event event.example_gateway_virtual_event --output output
```

4. 将示例 MAC 和网关 ID 换成自己的；如果仅有 ZS800J，只保留 ZS800J 的 `--device` 参数。
5. 终端显示「已生成 … 条事件及控制面板」后，打开项目目录中的 `output` 文件夹。生成操作只写本地文件，不会连接或操作马桶。

使用相同参数重新生成会覆盖该输出目录中的三个同名文件。修改过生成配置时先另存备份。

输出文件：

| 文件 | 用途 |
| --- | --- |
| `output/automation.yaml` | 一条 HA 自动化，将允许的事件名称转为服务调用 |
| `output/dashboard.yaml` | 设置 / 操作 / 默认模式配置 / 省电模式配置四个视图的原生 HA 面板 |
| `output/米家事件名称.md` | 本次配置对应的手机米家事件名称表 |

文件使用 JSON 语法保存，JSON 也是合法 YAML，HA 的 YAML 编辑器可以读取。输出含你的设备地址标识，请自行保管，不要将真实配置提交到公开仓库。

生成器按新安装的默认实体 ID 生成路由，例如：

```text
switch.jomoo_sq9650_aabbccddee01_night_light
select.jomoo_zs800j_aabbccddee02_seat_temp_level
```

如果你在 HA 重命名过实体，或旧实体导致 HA 加了编号，请以 HA 实际 ID 为准，修改生成文件中的 `entity` 值；改变设备显示名称不会自动改变路由目标。

## 3. 安装 HA 自动化

1. 进入「设置 → 自动化与场景 → 创建自动化 → 创建新的自动化」。
2. 右上角菜单切换为「在 YAML 中编辑」。
3. 将 `automation.yaml` 全文粘贴到该编辑器并保存。
4. 确认新自动化启用，检查触发器中的网关事件实体是否正确。

这是**单条自动化对象**，不是整个 `automations.yaml` 列表。若选择通过文件编辑，请把它作为列表中的一个项目合并，保留其他自动化，并检查配置、重新加载自动化。

## 4. 安装 HA 控制面板

1. 在「设置 → 仪表盘」中新建一个空白仪表盘，例如「九牧智联桥」。
2. 打开该仪表盘，进入编辑，打开「原始配置编辑器」。必要时先接管该新仪表盘。
3. 将 `dashboard.yaml` 全文粘贴保存。
4. 核对「设置」「操作」「默认模式配置」「省电模式配置」四页的实体都存在。

不要在已有家庭主面板中直接覆盖原始配置。若只想加入卡片，可从生成文件中复制对应卡片到自己的面板。

## 5. 手机米家创建场景

以 SQ9650 夜灯为例（别名使用 `sq9650` 时）：

| 场景名称，可自己命名 | 动作 | 事件名称，需完全一致 |
| --- | --- | --- |
| SQ9650 夜灯开 | 中枢网关 → 产生虚拟事件 | `jomoo_sq9650_night_light_on` |
| SQ9650 夜灯关 | 中枢网关 → 产生虚拟事件 | `jomoo_sq9650_night_light_off` |

### 在米家 App 中逐步添加

1. 打开「智能」页，点击右上角添加自动化 / 场景。
2. 「如果」选择「手动执行」。若你是把动作加到已有自动化，可直接编辑它的「就执行」部分。
3. 「就执行」选择智能设备，找到你家的 Xiaomi 中枢网关。
4. 在网关支持的动作中选择「产生虚拟事件」。
5. 在事件名称中粘贴对应名称，确认保存动作。
6. 为场景设置容易辨认的中文名称，例如「主卫 · 夜灯开」，再保存整个场景。
7. 点一次场景执行按钮，等待 HA 读回；不要一口气反复点击。

米家版本不同，菜单可能显示为「智能」「自动化」「场景」或「添加执行动作」，关键是最终选择网关的「产生虚拟事件」。

在手机的事件名称输入框内**直接填文字，不加中文引号、不加双引号、不加方括号、不加空格**：

```text
jomoo_sq9650_night_light_on
```

温度等多档设置各有自己的事件名称，复制本次生成的名称表。例如 ZS800J 座温偏低为 `jomoo_zs800j_seat_temp_level_2`。数字是协议档位，不是摄氏温度。米家自动化的执行动作中同样可选择「产生虚拟事件」，使用这些名称即可。

米家里的场景可以按房间和用途起中文名；只有事件字段需要保留生成表中的英文标识。

### 用一个事件切换整套默认 / 省电配置

在 HA 的两个模式配置页分别保存目标，然后在米家同样选择「中枢网关 → 产生虚拟事件」：

| 控制范围 | 默认模式 | 省电模式 |
| --- | --- | --- |
| 全部已配置设备 | `jomoo_mode_default` | `jomoo_mode_eco` |
| 别名 sq9650 | `jomoo_sq9650_mode_default` | `jomoo_sq9650_mode_eco` |
| 别名 zs800j | `jomoo_zs800j_mode_default` | `jomoo_zs800j_mode_eco` |

模式事件不需要 `--include-actions`。修改 HA 中的模式配置后，米家事件名称不变。默认模式初始不主动更改任何项目，须先编辑具体目标；详细升级与编辑步骤见[自定义模式教程](自定义模式.md)。

## 6. 验证整条链路

1. 先确认 HA 能直接控制灯光，手机未占用蓝牙。
2. 在米家执行一次场景，查看 HA 网关事件实体是否更新时间和 `事件名称`。
3. 打开「九牧智联桥：米家虚拟事件」自动化的运行轨迹，查看是否命中路由并调用正确实体。
4. 查看马桶实体读回及现场变化。

手机显示场景执行完成，只能证明米家执行了场景，不能替代马桶状态读回。命令失败会在 HA 自动化轨迹或日志显示，不会自动回传为米家马桶的原生状态。

路由忽略未知事件、超过 30 秒的事件、恢复的历史状态以及从 `unknown/unavailable` 状态到可用的首次事件，防止重启时误执行旧指令。网关刚恢复时第一条可能被忽略；确认实体稳定后再发起测试。请保证 HA 与网关时间正常。

### 可选：在 HA 中测试“产生事件”

如果 Xiaomi Home 暴露了发送事件的通知实体，可在开发者工具「动作」中测试。这里的 `notify` 接口与手机表单格式不同：

```yaml
action: notify.send_message
target:
  entity_id: notify.YOUR_GATEWAY_EMIT_ENTITY
data:
  message: '["jomoo_sq9650_night_light_on"]'
```

将目标替换为自己的通知实体。`["..."]` 是此通知接口的消息参数封装，**不是手机事件名称的填写方式**。不同上游版本以实际动作定义为准。

## 7. 可选：接入立即执行的动作

默认路由包含设置、蓝牙释放和默认 / 省电模式事件。若确认需要把翻盖、冲水、清洁维护操作也放进米家，在生成命令中添加：

```text
--include-actions
```

重新导入生成的自动化即可。此时名称表会增加以 `_press` 结尾的事件，例如 `jomoo_zs800j_flush_large_press`。

这些事件会真正启动机械动作；「自动冲刷开关」只是功能设置，与「大冲」按钮不同。动作入口尚未逐项实机验收，初次使用应在现场验证。超时可能代表动作已发生但反馈缺失，请勿连续重复触发。

## 按步骤判断故障在哪一层

| 你看到的结果 | 优先检查 | 成功标准 |
| --- | --- | --- |
| HA 根本找不到九牧智联桥 | 文件位置、是否重启、HA 日志 | 添加集成列表能搜索到名称 |
| 已添加但马桶不可用 | 手机占用、MAC、距离、Bluetooth 集成 | 实体显示实际档位与状态 |
| HA 能控制，米家执行后没有网关事件 | 网关功能入口、Xiaomi Home 导入、账号家庭 | `event.` 实体时间更新 |
| 有网关事件，路由没执行 | 名称、属性键、自动化启用状态、历史事件过滤 | 自动化轨迹进入动作步骤 |
| 路由执行但找不到实体 | 生成 MAC、实际实体 ID、是否重命名 | 动作目标是现有马桶实体 |
| 动作报设备忙或未确认 | 着座、运行状态、蓝牙完整反馈 | 空闲后单次操作得到读回 |
| 手机场景完成但现场没变化 | 看 HA 轨迹与实体读回，不只看米家提示 | 目标状态与现场一致 |

### 如何查看自动化运行轨迹

打开「设置 → 自动化与场景」，进入「九牧智联桥：米家虚拟事件」，打开「运行轨迹 / 跟踪」。选择最近一次运行，先看触发器数据，再看条件是否通过，最后看调用动作的目标实体和错误信息。若完全没有新轨迹，优先检查自动化是否启用、触发实体是否正确。

### 如何查看集成日志

打开「设置 → 系统 → 日志」，按九牧或 `jomoo_local` 查找。提交问题时仅复制相关错误片段并脱敏，不要上传完整配置或账号信息。已经发出的机械动作超时，先查看现场，不要立即重复执行。

## 8. 使用九牧小程序

米家或 HA 开启「释放蓝牙给小程序」→ 等待 HA 断开 → 手机连接并使用 → 退出小程序、断开手机 → 关闭「释放蓝牙给小程序」。

释放期间，设备控制实体显示不可用是预期行为；释放开关本身仍可操作。关闭释放开关会恢复 HA 连接，前提是手机已真正断开。
