# 蓝牙连接方式与米家动作指令

从 **0.6.1** 起，每台设备可以在 HA 独立选择长连接或按需连接。连接方式不会改变默认 / 省电模式的目标值，米家调用模式的事件名称也不变。

## 1. 选择适合自己的连接方式

| 设置 | 保持蓝牙连接开启 | 保持蓝牙连接关闭 |
| --- | --- | --- |
| 连接策略 | 长连接 | 按需连接 |
| 平时是否占用马桶蓝牙 | 是 | 否 |
| 状态更新 | 空闲约 30 秒一次，运行时约 5 秒一次 | 执行指令、模式或手动读取时更新 |
| 一次操作结束后 | 保持连接 | 完成或失败后断开 |
| 意外断线后 | 自动尝试恢复 | 等下一次指令，不后台重连 |
| 指令响应 | 通常更快 | 多出扫描、连接的等待 |
| 适合用途 | 经常操作、需要持续观察状态 | 定时切换模式、偶尔操作、需要手机使用小程序 |

新安装及未设置过该选项的旧版本升级，默认保留长连接行为；**想按需连接，请主动关闭“保持蓝牙连接”**。每台单独保存，HA 重启后保留。按需模式在 HA 启动时不会主动连接。

“保持蓝牙连接关闭”不等于禁用设备。HA 收到控制事件时仍会尝试连接；“释放蓝牙给小程序”则会禁止 HA 主动连接和控制，适用于需要明确暂停 HA 自动化的情况。

## 2. 安装或升级后在 HA 设置

1. 更新完整的 `custom_components/jomoo_local` 文件夹至 0.6.1 或更新版本，然后重启 HA。
2. 使用新版生成器，以原来的设备别名、MAC 和网关事件实体重新生成配置。
3. 更新已有九牧路由自动化与专用仪表盘。不要新增第二条相同路由，以免重复响应事件；自定义过面板布局时，只合并新增视图与实体。
4. 打开「九牧智联桥 → 蓝牙连接设置」。新版面板共五页：设置、操作、默认模式配置、省电模式配置、蓝牙连接设置。
5. 找到对应设备，将「保持蓝牙连接」关闭，即切换为按需连接。希望保持长连接时再打开。
6. 点击「读取一次最新状态」。成功读取后，按需模式的连接状态应回到「等待指令（按需连接）」。

也可以在「设置 → 设备与服务 → 九牧智联桥 → 对应设备」中找到该配置开关。无需增加新的插件、网关或硬件。

按需模式下，温度与开关显示的是**最后一次读回值**。实体详情包含「连接策略」「上次读取时间」「上次错误」。如果在小程序里修改了设置，HA 不会立即知道，需要下一次操作或手动读取后更新。HA 重启后尚未读取的值显示未知，模式编辑页保存的目标仍然保留。

控制入口可用表示可以发起请求，不保证蓝牙设备当前在线。若手机占用连接、距离过远或马桶断电，操作会报告错误；解决原因后可再次发起请求。

## 3. 默认 / 省电模式怎样连接

按需模式按每台设备执行下面的流程：

```mermaid
flowchart LR
    A[米家事件或 HA 应用按钮] --> B[连接并读取实际状态]
    B --> C[依次应用已保存的模式目标]
    C --> D[读取并核对结果]
    D --> E[断开蓝牙]
```

同一台马桶的整套模式共用一次连接，不会每修改一个选项都重新连接。发生错误或取消时也会尝试关闭连接。模式中途失败可能已有部分设置生效，不会自动回滚；请查看 HA 轨迹和实际状态。

模式配置与操作请求按设备排队。按需模式不做后台轮询；如果你另外配置了定时 `homeassistant.update_entity`、手动读取事件或其他控制自动化，它们仍会主动连接设备。

手机和主机不能同时占用同一台马桶的连接。定时任务执行时如果手机仍连接着马桶，任务可能失败。使用完小程序后请断开手机连接。

## 4. 在米家切换连接方式或读取状态

米家执行动作选择「Xiaomi 中枢网关 → 产生虚拟事件」。以下适用于生成器别名为 `sq9650`、`zs800j` 的情况，别名不同以自己生成的事件表为准。

| 用途 | SQ9650 事件名称 | ZS800J 事件名称 |
| --- | --- | --- |
| 切为按需连接 | `jomoo_sq9650_persistent_connection_off` | `jomoo_zs800j_persistent_connection_off` |
| 切为长连接 | `jomoo_sq9650_persistent_connection_on` | `jomoo_zs800j_persistent_connection_on` |
| 读取一次最新状态 | `jomoo_sq9650_refresh_state` | `jomoo_zs800j_refresh_state` |

连接方式通常在 HA 设置一次即可，无需每次定时任务先切换。模式事件继续使用 `jomoo_mode_default` 和 `jomoo_mode_eco`，详见[自定义模式教程](自定义模式.md)。

## 5. 开盖、关盖、冲水等动作指令

动作按钮在 HA 面板始终提供。**公开版默认路由不启用机械动作事件**；如果需要通过米家调用，在原有生成命令中增加 `--include-actions`：

```bash
python3 scripts/generate_config.py \
  --device sq9650=sq9650=AA:BB:CC:DD:EE:01 \
  --device zs800j=zs800j=AA:BB:CC:DD:EE:02 \
  --gateway-event event.example_gateway_virtual_event \
  --include-actions \
  --output output
```

用自己的 MAC、别名和网关实体替换示例。重新生成后，将 `output/automation.yaml` 导入**已有**九牧自动化并保存、启用；然后在米家填写对应动作事件。只复制事件名称、没有更新 HA 路由，不会执行动作。

两台示例默认启用 82 条设置、模式及连接管理事件；加上 `--include-actions` 后共 101 条。事件表始终列出下面的 19 条动作名称，未启用时会明确标注。

| 立即执行的动作 | SQ9650 事件名称 | ZS800J 事件名称 |
| --- | --- | --- |
| 开盖 | `jomoo_sq9650_open_cover_press` | `jomoo_zs800j_open_cover_press` |
| 关盖 | `jomoo_sq9650_close_cover_press` | `jomoo_zs800j_close_cover_press` |
| 翻起座圈 | `jomoo_sq9650_open_ring_press` | `jomoo_zs800j_open_ring_press` |
| 放下座圈 | `jomoo_sq9650_close_ring_press` | `jomoo_zs800j_close_ring_press` |
| 大冲 | `jomoo_sq9650_flush_large_press` | `jomoo_zs800j_flush_large_press` |
| 小冲 | `jomoo_sq9650_flush_small_press` | `jomoo_zs800j_flush_small_press` |
| 魔力泡 | `jomoo_sq9650_bubble_press` | `jomoo_zs800j_bubble_press` |
| 待机 | `jomoo_sq9650_hibernate_press` | 不提供 |
| 自清洁模式 | 不提供 | `jomoo_zs800j_self_clean_press` |
| 喷嘴清洁 | 不提供 | `jomoo_zs800j_nozzle_clean_press` |
| 更换喷嘴 | 不提供 | `jomoo_zs800j_replace_nozzle_press` |
| 停止清洁 / 维护 | 不提供 | `jomoo_zs800j_stop_clean_press` |

手机事件名称输入框只填写一个英文标识，不加引号、方括号或参数。例如 ZS800J 开盖：

```text
jomoo_zs800j_open_cover_press
```

`auto_flush_on` 是开启自动冲刷功能，`flush_large_press` 是立即大冲，两者作用不同。以 `_press` 结尾的动作会真正启动设备功能；初次使用请在设备空闲时现场验证。超时可能代表动作已执行但反馈缺失，先查看现场，不要连续重试。

## 验证范围

按需连接已在 SQ9650、ZS800J 的家庭版本中实测读取成功后断开，并验证长连接开关可切换。公开版沿用相同连接生命周期，并通过 HA API 隔离测试；完整模式组合、全部机械动作和不同硬件批次没有逐项实机验收。

其余依赖与排查见[安装与依赖](安装与依赖.md)、[米家接入](米家接入.md)和[功能与验证范围](功能与验证.md)。
