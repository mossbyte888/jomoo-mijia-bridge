# 自定义默认模式与省电模式

从 **0.6.0** 起，每台马桶都可以在 HA 中分别编辑、保存两套设置，再用一个米家事件应用整套配置。模式只调整已有的温度、开关与档位，不执行翻盖、冲水或清洁动作。

## 1. 两个模式分别是什么

| 模式 | 用途 | 新安装时的通用模板 |
| --- | --- | --- |
| 默认模式 | 自己定义日常使用的设置 | 所有项目为「保持现状」，未编辑时不会更改设置 |
| 省电模式 | 自己定义离家、夜间等场景的设置 | SQ9650 座温常温；ZS800J 座温、水温、风温常温，四季温感关闭；其他项目保持现状 |

**默认模式不是恢复出厂设置，省电模式也不是断电或马桶内置的某个隐藏开关。** 名称用于区分两套可编辑的目标，不代表固定温度或保证节电比例。修改后以你保存的选项为准。

「保持现状」表示该模式不主动改这一项，不会记录当前值供以后恢复。如果希望默认模式恢复座温，就必须在默认模式中明确选择座温档位。

所有模板均为通用初始值，不包含任何家庭的实际配置、作息或设备地址。安装、升级、HA 重启都不会自动应用模式。

## 2. 安装或升级

首次安装请先完成[安装与依赖](安装与依赖.md)和[米家接入](米家接入.md)。从 0.5.0 升级时：

1. 备份 HA 配置及现有九牧自动化和面板。
2. 更新完整的 `custom_components/jomoo_local` 文件夹，确保包括 `presets.py` 和 `preset_config.py`，然后重启 HA。
3. 在马桶的设备页确认出现「默认模式 · …」「省电模式 · …」配置实体，以及「应用默认模式」「应用省电模式」按钮。
4. 用新版 `scripts/generate_config.py` 和自己的 MAC、别名、网关事件实体重新生成配置，命令与旧版相同，无需添加参数。
5. 在原有「九牧智联桥：米家虚拟事件」自动化中替换 YAML 并保存。**不要重复创建第二条同样的路由自动化。**
6. 更新九牧专用仪表盘的原始配置；如果改过布局，只合并生成文件中的两个模式视图及按钮，保留自己的卡片。
7. 确认面板包含「设置」「操作」「默认模式配置」「省电模式配置」四个功能页；0.6.1 另外提供「蓝牙连接设置」页。

不需要新增插件，不需要导入 `scripts.yaml`，无需 MQTT、Node-RED 或第三方卡片。配置实体的 ID 含型号及蓝牙 MAC 标识，同型号多台设备互不共用模式。

如果你以前自行创建过同名米家事件的脚本路由，请停用或移除那条旧路由，避免新旧规则同时响应。私有定制版的数据格式与本公开版不同，不能直接复制其存储文件。

## 3. 在 HA 编辑模式

1. 打开「默认模式配置」。找到要配置的那台马桶。
2. 温度、风速等从下拉菜单选择目标档位；开关项目选择「开启」「关闭」或「保持现状」。
3. 每次修改都会单独保存。**编辑模式不会发送蓝牙控制指令，也没有额外的“保存整套”按钮。** 保存失败时 HA 会报错，不会把未保存值显示为成功。
4. 切换到「省电模式配置」，同样设置另一套目标。
5. 检查两页后，在马桶空闲、手机已断开蓝牙时，点击「应用默认模式（本台）」或「应用省电模式（本台）」测试。
6. 回到「设置」页确认真实读回值。配置页显示的是目标，设置页显示的是设备状态，两者含义不同。

例如，希望 ZS800J 平时座温偏低、离家后常温，而水温和风温始终不加热：

| 项目 | 默认模式目标 | 省电模式目标 |
| --- | --- | --- |
| 座温 | 偏低 | 常温 |
| 水温 | 常温 | 常温 |
| 风温 | 常温 | 常温 |
| 四季温感 | 关闭 | 关闭 |
| 其他功能 | 保持现状，或按需要明确选择 | 保持现状，或按需要明确选择 |

这只是填写示例，不会自动替你设定作息或更改默认模式的初始模板。SQ9650 的座温可选常温、中温、高温；请按对应型号菜单选择。

## 4. 米家需要填写的事件名称

以下单台名称适用于生成命令中的别名为 `sq9650`、`zs800j`。全部设备的两个事件名称固定；若修改别名，单台事件会随之改变，以自己生成的 `米家事件名称.md` 为准。

| 希望执行 | 事件名称 | 控制范围 |
| --- | --- | --- |
| 一起应用默认模式 | `jomoo_mode_default` | 本条生成路由包含的全部马桶 |
| 一起应用省电模式 | `jomoo_mode_eco` | 本条生成路由包含的全部马桶 |
| SQ9650 应用默认模式 | `jomoo_sq9650_mode_default` | 别名为 sq9650 的设备 |
| SQ9650 应用省电模式 | `jomoo_sq9650_mode_eco` | 别名为 sq9650 的设备 |
| ZS800J 应用默认模式 | `jomoo_zs800j_mode_default` | 别名为 zs800j 的设备 |
| ZS800J 应用省电模式 | `jomoo_zs800j_mode_eco` | 别名为 zs800j 的设备 |

“全部”只包括这次生成配置时列出的设备，不会扫描或控制其他马桶。只有一台时，全部事件也只控制这一台。两台一起应用时，每台读取自己保存的目标，因此可使用不同温度。

### 在手机上创建两个快捷场景

1. 米家 → 智能 / 自动化 → 添加 →「如果」选择「手动执行」。
2. 「就执行」选择 Xiaomi 中枢网关 →「产生虚拟事件」。
3. 第一个场景的事件名称填写 `jomoo_mode_default`，中文场景名可写「马桶 · 默认模式」。
4. 第二个场景填写 `jomoo_mode_eco`，中文场景名可写「马桶 · 省电模式」。
5. 保存后，在现场各执行一次，查看 HA 自动化运行轨迹及各设备真实设置。

手机事件名称输入框只填英文标识，不加引号、方括号、参数、空格或温度值：

```text
jomoo_mode_default
```

```text
jomoo_mode_eco
```

两段分别用于两个场景，不要一起粘贴。米家场景名称可以任意起中文名；真正匹配路由的是动作中的事件名称。之后在 HA 修改模式内容，米家事件名称保持不变。

### 在定时、离家或回家自动化中使用

「如果」按自己的需求选择时间、日期、离家 / 回家条件；「就执行」直接添加中枢网关的「产生虚拟事件」动作，填写对应名称即可。也可以调用前面已创建的手动场景（以当前米家版本提供的动作入口为准）。不需要为每个温度和开关分别添加动作。

例如，“离家 → 产生 `jomoo_mode_eco`”，“回家 → 产生 `jomoo_mode_default`”。这只是配置方法，项目不会自行添加定时规则。

### 来电后恢复省电状态

若智能插座支持你需要的恢复供电触发条件，可在米家自行配置“恢复供电 → 延时 → 产生 `jomoo_mode_eco`”。延时应覆盖马桶开机、网关及 HA 网络恢复和蓝牙重连，先在自己的设备上验证后再确定时长。

“插座打开”和“整屋断电后来电”不一定是同一个事件；网关、HA 同时掉电时也可能错过触发。此功能不保证停电后的自动恢复，项目不内置断电检测或补发规则。

## 5. 特殊设置与执行方式

- **SQ9650 光感夜灯**：若应用后的光感夜灯为开启，普通夜灯交给设备自动控制，本次模式会跳过普通夜灯目标；若想固定夜灯开关，先在同一模式中把光感夜灯设为关闭。
- **ZS800J 预湿润与落座发泡**：预湿润关闭会联动关闭落座发泡，即使后者选择保持现状也无法阻止。若配置“预湿润关闭、落座发泡开启”，整台设备的本次模式会在写入前报错。预湿润保持现状且当前关闭时，单独要求开启落座发泡也会报错。
- **ZS800J 开启预湿润**：设备可能联动打开落座发泡；程序会随后恢复该模式要求的发泡状态，若发泡选择保持现状则恢复到本次执行前的状态。
- **四季温感**：如需固定座温、水温、风温，请将其设为关闭。开启后设备可能自动调温，配置的固定目标可能无法持续保持。
- **执行时快照**：收到模式请求时读取一份已保存目标；执行中继续编辑，只影响下一次请求。建议编辑完成后再触发米家。
- **逐台排队**：同一台设备的模式、普通设置和动作不会交错下发；轮询仍可读取状态。不同设备可以独立执行。
- **失败不是回滚**：模式逐项写入并核对，不是原子事务。中途断线、设备忙或释放蓝牙时可能已完成部分设置；另一台也可能已经成功。查看 HA 轨迹和实际状态，解决原因后再单次触发。
- **蓝牙交接**：释放给手机时仍可编辑模式，但不能应用；关闭释放开关并断开手机连接后再试。

## 6. 保存、备份与排查

模式按 HA 配置条目保存在 `/config/.storage/jomoo_local.presets_<entry_id>`，属于 HA 本地配置。应使用 HA 备份保留 `.storage`，不要在运行时手工修改文件。卸载设备再重新添加通常会得到新的条目 ID，需要重新配置模式；只重启 HA 会保留已保存的目标。

| 现象 | 处理方法 |
| --- | --- |
| 没有模式配置页 | 更新集成并重启，再生成、导入新版面板 |
| 下拉菜单有变化，马桶没变 | 编辑只保存；再执行应用按钮或米家事件 |
| 默认模式执行后温度没恢复 | 默认模式初始保持现状；明确填写希望恢复的温度 |
| 米家事件没反应 | 先确认网关事件有更新，再检查自动化 `variables.routes` 包含所填名称；仅有 `jomoo_mode_eco` 不会响应 `jomoo_sq9650_mode_eco`。更新集成后仍需重新生成并替换路由 |
| 提示实体不存在 | 检查生成参数和实际 HA 实体 ID，尤其是手工改名或旧实体编号 |
| 模式只生效一部分 | 查看本次轨迹错误和真实设备状态；不要把配置页当成执行结果 |
| 保存报错 | 检查 HA 存储空间及权限，恢复后重新选择并确认 |

完整事件列表见[米家事件名称](../examples/米家事件名称.md)，链路排查见[米家接入](米家接入.md)。新模式实现已完成 HA API 隔离测试；不将软件测试等同于所有型号、所有组合的实机验收。

## 可选：让模式执行后断开蓝牙

0.6.1 起，在「蓝牙连接设置」关闭该设备的「保持蓝牙连接」。模式执行时自动连接、读取、依次设置并核对，完成或失败后断开，不进行后台轮询。两种模式的目标与米家事件名称均不变，具体见[连接方式教程](蓝牙连接与动作指令.md)。
